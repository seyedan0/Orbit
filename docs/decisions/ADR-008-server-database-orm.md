# ADR-008: انتخاب TypeORM برای پایگاه داده PostgreSQL سرور NestJS

- **تاریخ:** 2026-09-30
- **وضعیت:** پذیرفته‌شده
- **زمینه:** در فاز ۳ و پیرو ADR-003، هسته سرور با NestJS و پایگاه داده PostgreSQL پیاده‌سازی می‌شود. برای نگاشت موجودیت‌های دامنه، ایجاد و اجرای مایگریشن‌ها، تضمین تراکنش‌های اتمیک در عملیات همگام‌سازی (`push`) و ارتباط پایدار با دیتابیس (مانند Neon PostgreSQL)، نیاز به انتخاب ORM یا Query Builder بود.
- **تصمیم:** استفاده از `@nestjs/typeorm` و `typeorm` همراه با درایور `pg`.
- **دلیل:**
  1. یکپارچگی بومی و درجه یک با سیستم تزریق وابستگی (DI) و معماری ماژولار NestJS.
  2. امکان تعریف مستقیم موجودیت‌ها با دکوراتورهای استاندارد TypeScript منطبق بر `docs/data-model.md`.
  3. پشتیبانی ساده و قدرتمند از تراکنش‌های اتمیک دیتابیس (`dataSource.transaction`) برای ثبت هم‌زمان entity و mutation در عملیات push.
  4. عدم نیاز به موتورهای باینری اختصاصی یا مراحل تولید کد اضافی در ساختار monorepo.
  5. مدیریت شفاف schema migrationها و تطابق کامل با استانداردهای سازمانی NestJS.
- **پیامدها:** موجودیت‌های دیتابیس تحت `apps/server/src/database/entities/` ایجاد شده و `PostgresSyncRepository` با استفاده از `DataSource` و تراکنش‌های TypeORM پیاده‌سازی می‌شود.
- **جایگزین‌ها:**
  - Prisma: نیازمند مرحله تولید کد (`prisma generate`) و باینری‌های مجزا در monorepo.
  - Drizzle / Kysely: انتزاع مناسب اما یکپارچگی کمتر با اکوسیستم DI در NestJS نسبت به TypeORM.
  - raw `pg`: فاقد مدیریت ساختاریافته مدل‌ها و مایگریشن‌ها.
